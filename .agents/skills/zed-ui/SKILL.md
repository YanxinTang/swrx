# Zed 官网 UI 设计规范

## 1. 设计风格定位

核心风格：**编辑式极简主义 + 工程化精确感**。

- **编辑感**：衬线标题搭配简洁的无衬线正文，形成类似技术刊物的视觉层次。
- **工程感**：使用精细边框、网格线、几何标记和规整布局，呈现工程制图般的秩序感。
- **克制的强调色**：使用项目定义的 `accent-blue`，避免大面积高饱和色彩。
- **低装饰性**：依靠字体、排版、留白和边界建立层次，而非大量阴影、渐变和圆角卡片。
- **统一的设计系统**：颜色必须引用项目已有的 Tailwind CSS 主题 Token，不得硬编码颜色值或重复定义同义颜色。

## 2. 色彩系统

### 2.1 强制规范

所有颜色优先使用项目 `@theme` 中已定义的 Token。

禁止：

- 在组件中直接写 HEX、RGB、HSL、LAB、OKLCH 等颜色值。
- 使用 `style={{ color: '#...' }}` 之类的内联颜色。
- 为单个组件创建与现有 Token 重复的颜色变量。
- 使用 Tailwind 默认调色板替代已有的 `cream-*`、`offgray-*` 和 `accent-blue`。

推荐使用以下工具类：

| 使用场景 | 推荐 Token |
|---|---|
| 品牌强调色、主要链接、图标 | `accent-blue` |
| 强调色背景 | `bg-accent-blue` |
| 浅色暖调表面 | `bg-cream-50` |
| 暖调边界或次级表面 | `border-cream-100`、`bg-cream-100` |
| 暖调文字或装饰 | `text-cream-700`、`text-cream-900` |
| 浅色中性背景 | `bg-offgray-50` |
| 次级文字 | `text-offgray-500`、`text-offgray-600` |
| 常规边界 | `border-offgray-200`、`border-offgray-300` |
| 深色表面 | `bg-offgray-950` |
| 深色背景 | `bg-offgray-1000` |
| 深色文字 | `text-offgray-50`、`text-offgray-100` |
| 深色边界 | `border-offgray-800`、`border-offgray-900` |

根据实际背景、文字对比度和视觉层级选择 Token，不要机械地套用表格。

### 2.2 浅色主题

- 使用 `cream-50`、`offgray-50` 等浅色 Token 建立干净的背景。
- 使用 `offgray-900`、`offgray-950` 等深色 Token 建立文字层次。
- 使用 `offgray-200`、`offgray-300` 等 Token 绘制网格线和组件边界。
- 使用 `accent-blue` 作为主要强调色。
- 暖调区域优先使用 `cream-*`，中性区域优先使用 `offgray-*`，避免整个页面只有一种灰色。

### 2.3 深色主题

- 使用 `offgray-1000`、`offgray-950` 等 Token 构建深色背景与表面。
- 使用 `offgray-50`、`offgray-100` 等 Token 展示主要文字。
- 使用 `offgray-800`、`offgray-900` 等 Token 绘制分隔线。
- 保持 `accent-blue` 的品牌识别；需要更高对比度时，优先利用现有 Token 和透明度修饰符，不得自行引入硬编码颜色。
- 使用项目现有的主题机制实现深浅色切换，避免在组件中散落颜色判断。

### 2.4 透明度与衍生色

允许使用 Tailwind 的透明度修饰符表达交互状态，例如：

```html
<div class="bg-accent-blue/10">
  ...
</div>

<div class="border border-offgray-300/50">
  ...
</div>

<p class="text-offgray-600/80">
  ...
</p>
```

如果项目构建配置支持 `color-mix()` 等机制，可以集中维护衍生颜色，但不要让每个组件自行定义颜色。

禁止使用 `bg-[#...]`、`text-[hsl(...)]` 等任意颜色工具类。

## 3. 字体与排版

### 3.1 字体角色

使用项目现有的字体配置，不重复引入或定义字体。

| 使用场景 | 字体 Token |
|---|---|
| 常规正文 | `font-sans` |
| 通用等宽文字 | `font-mono` |
| 技术信息、代码、标签 | `font-zed-mono` |
| 编辑感标题、强调性文案 | `font-plex-serif` |

字体角色应与项目 `@theme` 中的实际定义保持一致。

推荐搭配：

- **大标题**：使用 `font-plex-serif`，采用轻至常规字重，适当控制行高。
- **正文**：使用 `font-sans`，保持清晰、克制、易读。
- **导航、版本号、技术标记**：使用 `font-zed-mono`，通过字距与大写营造技术感。
- 重要标题优先通过字体风格建立层次，不要只依靠超大字号和粗体。

### 3.2 小标题标签

优先复用已有的 `subheader` 工具类。

```html
<p class="subheader text-offgray-600">
  PRODUCT OVERVIEW
</p>
```

`subheader` 已封装等宽字体、字距、字号和大写转换，不要在每个组件中重复实现。

### 3.3 文字层级

- **主标题**：强调字体气质、行高与文字节奏。
- **正文**：控制阅读宽度，避免过长的连续文本。
- **次级说明**：使用合适的 `offgray-*` Token。
- **技术标签**：使用等宽字体和紧凑间距。
- 不要让所有文字使用相同字重、字号或对比度。

## 4. 布局与网格

### 4.1 页面结构

- 使用清晰的容器宽度、规则的列布局和明确的水平分区。
- 大屏采用多列网格，小屏调整为单列或少列布局。
- 重要内容应有充足的上下留白。
- 通过对齐、间距和边界构建层次，而不是给每个区块增加独立的卡片背景。
- 适当使用贯穿页面的水平分隔线，建立统一的版面节奏。
- 长篇内容可以参考项目已有的 `--blog-content-width` 和 `--markdown-layout-width` 控制阅读宽度。

### 4.2 网格装饰

工程制图式的网格装饰是 Zed 风格的重要视觉特征。

- 使用细边框构建布局分区。
- 在容器边缘、分隔线交点等位置使用小型几何标记。
- 可以使用小菱形、十字或短线作为装饰元素。
- 装饰应与网格对齐，不应随机漂浮。
- 边框使用 `border-offgray-*` 或适合当前主题的 `border-cream-*`。
- 几何装饰使用 `text-offgray-*`、`text-cream-*` 或 `text-accent-blue`。

装饰性元素应使用独立的 CSS 或 SVG 实现，避免把复杂的几何图形写成难以维护的内联样式。

## 5. 边框、表面与形状

### 5.1 边框

- 优先使用 1px 细边框。
- 使用低对比度 Token 作为分隔线。
- 重要区域可以使用较高对比度的边界，但不要到处强调。
- 可以使用双边框、分段边框或边角标记增强技术感。

### 5.2 表面

- 页面主要依靠背景和边界区分区域。
- 使用 `cream-*` 营造暖调、纸张感的区域。
- 使用 `offgray-*` 构建中性表面和深色区域。
- 避免不必要的层层嵌套卡片。

### 5.3 圆角

- 优先使用小圆角或直角。
- 输入框、按钮和卡片的圆角应保持一致。
- 不要将所有组件设计成大圆角胶囊。
- 只有在语义合适时，才使用完全圆形的图标按钮或胶囊按钮。

### 5.4 阴影

- 阴影应轻微且有明确用途。
- 优先使用项目已有的 `drop-shadow-sm`、`drop-shadow-md`。
- 不要使用厚重阴影模拟悬浮层级。
- 平面布局优先依靠边界、背景和间距建立层次。

## 6. 组件设计规范

### 6.1 导航栏

- 导航布局简洁、紧凑。
- 使用统一的字体、间距和对齐规则。
- 当前选中项可以使用 `accent-blue`。
- 分隔线和次级信息使用 `offgray-*` Token。

### 6.2 按钮

- **主要按钮**：使用 `bg-accent-blue`，搭配具有足够对比度的文字。
- **次要按钮**：使用透明或中性背景，通过 `border-offgray-*` 建立边界。
- **悬停状态**：使用透明度、现有 Token 或轻微背景变化。
- **按下状态**：可以使用轻微位移或缩放。
- **禁用状态**：明确体现不可交互性。

避免用不同的硬编码颜色为每个按钮制造独立风格。

### 6.3 卡片

- 卡片不应成为默认布局单元。
- 需要分组时，优先使用细边框和清晰的内容间距。
- 背景从 `cream-*`、`offgray-*` 中选择。
- 避免大面积渐变、厚重阴影和过度圆角。

### 6.4 图标

- 优先复用项目图标体系。
- 使用 `icons-base` 作为基础图标样式。
- 需要品牌强调时复用 `accent-blue`；普通图标根据上下文使用 `offgray-*`。
- 保持图标尺寸、描边风格和视觉重量一致。
- 不要使用大量风格不统一的 Emoji 代替功能图标。

## 7. 背景与装饰细节

- 背景装饰应保持低对比度，不影响主要内容。
- 可以使用网格、线条、角标、微弱纹理和少量渐变。
- 渐变优先基于已有主题 Token 派生，不要新增硬编码颜色。
- 大面积装饰不能削弱标题和正文的可读性。
- 装饰性元素应允许在小屏幕上简化或隐藏。

## 8. 交互与动效

- 默认过渡时间使用项目的 `--default-transition-duration`。
- 默认缓动使用项目的 `--default-transition-timing-function`。
- 使用现有的 `animate-spin-slow`、`animate-spin-slower`、`animate-fade` 和 `animate-fade-up`，前提是动画语义匹配。
- 悬停反馈应克制、迅速且一致。
- 按钮按下可以使用轻微位移或缩放。
- 装饰性动画不应干扰阅读或持续吸引注意力。
- 尊重 `prefers-reduced-motion`，为减少动态效果的用户提供合理体验。

## 9. 响应式设计

- 移动端优先保证内容可读性和操作便利性。
- 使用项目已有的断点配置，不要随意定义重复断点。
- 多列网格在窄屏下应降为少列或单列。
- 缩小装饰元素的密度，避免边框和角标互相拥挤。
- 标题字号应随视口合理变化。
- 不要为了维持桌面版的装饰效果而牺牲移动端布局。

## 10. 无障碍设计

- 确保文字与背景具有足够的对比度。
- 不要仅依赖颜色表达状态。
- 焦点状态应清晰可见。
- 按钮、链接和输入框应具有正确的语义。
- 交互区域应有足够的点击面积。
- 动画应支持减少动态效果的系统设置。
- 深浅色主题都需要检查文字、边框、图标和禁用状态的对比度。

## 11. 实现规范

### 11.1 必须遵守

1. 使用项目现有的 Tailwind CSS 4 主题 Token。
2. 颜色类优先使用 `bg-accent-blue`、`text-offgray-600`、`border-offgray-200` 等语义明确的工具类。
3. 字体使用 `font-sans`、`font-mono`、`font-zed-mono`、`font-plex-serif` 等已配置字体 Token。
4. 复用 `subheader` 和 `icons-base` 等现有工具类。
5. 优先组合已有 Token，不要为单个页面创建重复的颜色体系。
6. 如果缺少某种颜色，不要直接写任意颜色值；优先选择现有 Token 中视觉和语义最接近的值。确实需要新增颜色时，应先扩展中央主题配置。

### 11.2 禁止的写法

```tsx
// 不要直接硬编码颜色
<div className="bg-[#0d0d0f] text-[#e3e4e7] border-[#35383f]">
  ...
</div>

// 不要在组件中直接定义颜色
<div style={{ color: '#1348dc' }}>
  ...
</div>
```

### 11.3 推荐的写法

```tsx
<div className="bg-offgray-1000 text-offgray-50 border border-offgray-900">
  <h1 className="font-plex-serif">
    构建更好的开发体验
  </h1>

  <p className="font-sans text-offgray-300">
    专注于软件开发的高性能环境。
  </p>

  <button className="bg-accent-blue text-white">
    开始使用
  </button>
</div>
```

以上示例中的颜色均引用项目已有的主题 Token，未直接定义颜色值。

## 12. 应避免的设计模式

- 大面积高饱和色块。
- 厚重阴影和过度圆角。
- 无意义的玻璃拟态。
- 每个区域都使用独立卡片包裹。
- 大量无规则的渐变和发光效果。
- 过度粗重的标题与密集的全大写文本。
- 缺乏层级的统一灰色布局。
- 直接硬编码 HEX、RGB、HSL、LAB 或 OKLCH 颜色。
- 在组件中重复声明项目已经提供的字体、颜色和动画。
- 使用与项目主题 Token 不一致的 Tailwind 默认颜色替代已有配置。
